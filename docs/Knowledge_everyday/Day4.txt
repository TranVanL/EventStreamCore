1. Semaphore 
- Semaphore is a kernel synchronization primitive that maintains an internal counter.
It is mainly used for thread synchronization and resource counting.
wait() / acquire() / sem_wait() successfully : count - 1 
post() / release() / sem_post() successfully : count + 1

Architecture : 
wait() : if count > 0 : 
			count --;
			continue run 
		 else count == 0 : 
			block , put to wait queue ;

post() : count++;
		 notify a waiter if exist 

** Semaphore don't contain of owner . Thread A wait but thread B post() ;
-> Big different with mutex 
(binary semaphore can build like a basically mutex with a couple wait() , post() in each thread ) 
But it still has a massive diffent in : + Ownership (Mutex ensure only that thread can access critical and other mandatorily wait it done ! ) | (Prevent a lot of bug ) 
										+ System build for mutex ( mutex like a expert in protect data in critical section and many system build around that (Ex : Priority inheritance , ceiling , robust mutex ) ) 
										+ Code and Readability ( Mutex show explicit purpose )
